# **Загрузка системы**

Ниже рассмотрим два подхода к загрузке системы классический (BIOS \+ MBR) и современный (UEFI \+ GPT). Детально разбирается роль, архитектура и конфигурация загрузчика GRUB, его размещение на диске в разных сценариях. Показаны методы восстановления доступа к системе и восстановления самого загрузчика. 

основные понятия: *POST, BIOS, UEFI, GRUB, MBR, GPT, ESP, initramfs, Ядро (Kernel), SystemD, Recovery Mode* 

**Основные этапы загрузки Linux (Общая схема)** 

* Последовательность стадий одинакова для всех систем:

POST →  BIOS/UEFI →  Загрузчик (GRUB) →  Ядро \+ initramfs →  Корневая ФС (rootfs) →  SystemD (пользовательское пространство)

#### **Сравнение BIOS и UEFI**

| Критерий | BIOS (Legacy) | UEFI (Современный) |
| :---- | :---- | :---- |
| Интерфейс | Текстовый  | Графический, может иметь сетевой стек |
| Разметка диска | MBR | GPT  |
| Выбор загрузки | Указывается диск  | Указывается файл загрузчика на ESP  |
| Раздел загрузки | Код в первых секторах диска | Отдельный ESP-раздел (FAT32)  |

#### **Архитектура и стадии загрузчика GRUB** 

* GRUB является модульным и состоит из нескольких стадий, которые подгружаются по мере необходимости.

| Стадия / Компонент | Описание | Расположение |
| :---- | :---- | :---- |
| **BIOS \+ MBR**  |  |  |
| Stage 1 | Первичный код, помещаемый в 446 байт MBR. Слишком мал для всей логики.  | Первый сектор диска (MBR) |
| Stage 1.5 | Промежуточный код (\~32 Кб). Помогает прочитать ФС и загрузить Stage 2\.  | Следующие сектора после MBR (например, 34-й сектор для GPT)  |
| Stage 2 | Основная логика загрузчика. Загружает ядро, initramfs, предоставляет меню.  | Файлы в /boot/grub/ (модулы .mod, конфиг grub.cfg)  |
| **UEFI \+ GPT**  |  |  |
| EFI-файл | Единый исполняемый файл загрузчика. Аналог Stage 1 и Stage 2\. | ESP/EFI/ubuntu/grubx64.efi  |
| Модули (Stage 2\) | Дополнительные функции (работа с ФС, сценарии). Подгружаются основным .efi-файлом.  | /boot/grub/ (на основном разделе)  |

**Важно:** В UEFI-системе GRUB не использует MBR и Stage 1.5. Он загружается напрямую из ESP-раздела.

#### **Файловая структура и конфигурация GRUB** 

***Ключевые каталоги и файлы***

* /boot/grub/: Основное расположение конфигурации GRUB и модулей.  
* /boot/grub/grub.cfg: Главный конфигурационный файл, который нельзя редактировать вручную, так как он генерируется автоматически.  
* /etc/default/grub: Файл с основными настройками загрузчика. Изменения вносятся сюда, после чего применяется команда update-grub.  
* /etc/grub.d/: Директория со скриптами, которые генерируют отдельные секции grub.cfg 


***Управление конфигурацией***

* Процесс изменения настроек: редактирование /etc/default/grub \-\> выполнение команды update-grub \-\> автоматическая перегенерация grub.cfg.  
* Полезные настройки в /etc/default/grub:  
  * GRUB\_TIMEOUT=10: Время показа меню.  
    * GRUB\_TIMEOUT\_STYLE=menu: Показывать меню, а не скрывать его.  
    * GRUB\_CMDLINE\_LINUX\_DEFAULT="...": Параметры ядра для нормальной загрузки.  
    * GRUB\_DISABLE\_OS\_PROBER=false: Включение поиска других ОС (для dual-boot).

***Параметры ядра***

* Передаются в строке linux в grub.cfg.  
* Используются для отключения функций (IPv6), работы с железом или загрузки в специальных режимах.  
* Текущие параметры можно посмотреть в системе: cat /proc/cmdline.

#### **Практические аспекты: восстановление и диагностика** 

#### ***Восстановление пароля root*** 

*Способ 1:* Через редактирование пункта меню GRUB (для Debian/Ubuntu)

1. В меню GRUB нажмите e для редактирования.  
2. Найдите строку, начинающуюся с linux, и в параметрах ядра:  
* Замените ro на rw (чтение-запись).  
* Добавьте init=/bin/bash.  
3. Нажмите Ctrl+X или F10 для загрузки.  
4. Система загрузится прямо в root-шелл. Смените пароль командой passwd.  
5. Перезагрузитесь.

*Способ 2:* Использование single или rd.break (для Red Hat/CentOS)

1. Аналогично отредактируйте параметры ядра в GRUB.  
2. Добавьте параметры single или rd.break.  
3. После загрузки может потребоваться перемонтировать корневую ФС в режим RW: mount \-o remount,rw /sysroot.

#### ***Использование Recovery Mode*** 

Пункт меню в разделе Advanced Options. Предоставляет меню с вариантами восстановления:

* root: Открывает root-шелл (требует пароль, если он установлен).  
* network: Включает сеть и перемонтирует корневую ФС в RW.  
* fsck: Проверяет файловые системы.  
* grub: Обновляет конфигурацию GRUB.  
* clean: Очищает место на диске.

#### ***Восстановление загрузчика GRUB с LiveCD***

1. Загрузитесь с LiveCD.  
2. Определите и смонтируйте корневую ФС и раздел ESP (если есть):  
3. bash

mount /dev/sda1 /mnt

4. mount /dev/sda2 /mnt/boot/efi \# для ESP  
5. Подмонтируйте виртуальные файловые системы:  
6. bash

mount \--bind /dev /mnt/dev  
mount \--bind /proc /mnt/proc

7. mount \--bind /sys /mnt/sys  
8. Перейдите в окружение целевой системы: chroot /mnt.  
9. Переустановите GRUB:  
* Для BIOS: grub-install /dev/sda  
* Для UEFI: grub-install \--target=x86\_64-efi \--efi-directory=/boot/efi  
10. Обновите конфигурацию: update-grub.  
11. Выйдите из chroot и перезагрузитесь.

#### **Загрузка ядра и initramfs**

* Назначение initramfs: Содержит драйверы, утилиты и скрипты, необходимые ядру для монтирования настоящей корневой ФС (например, драйверы для LVM, шифрования).  
* Связь с ядром: Каждому ядру соответствует свой initramfs.  
* Обновление initramfs: Происходит автоматически при установке драйверов (например, NVIDIA). Вручную: update-initramfs \-u.  
* Структура initramfs:  
  * Можно распаковать и изучить: lsinitramfs /boot/initrd.img-... .  
  * Внутри содержится упрощенная корневая ФС с бинарниками (/bin), конфигами (/conf) и микрокодом процессора (/early).

#### **Выводы**

* Процесс загрузки – это цепочка. Сбой на любом этапе (POST, BIOS/UEFI, GRUB, ядро) приведет к отказу всей системы.  
* GRUB – это мост. Он является связующим звеном между firmware (BIOS/UEFI) и операционной системой (Ядро Linux). Его модульность позволяет работать в любой среде.  
* Понимание \= контроль. Знание того, как работает загрузка и где находятся ее ключевые компоненты, является фундаментальным навыком системного администратора, позволяющим диагностировать и исправлять широкий класс проблем, от сброса пароля до полного восстановления загрузчика.  
* Конфигурация GRUB управляема. Основные настройки меняются в /etc/default/grub, а не в автоматически генерируемом grub.cfg.
